# 公网与内网考试双向同步

适用范围：监考系统的 HYDRO 本机考试（`platformContestId=local`）。NovaJudge 和公开系统测试不提供此功能。本次仅更新后台网页、服务端和数据库；桌面客户端和考生网页无须修改。

## 配置步骤

1. 两端更新同一版本的后台及数据库结构。服务器 `SESSION_SECRET` 至少 32 字符并持久保存；两端密钥可以不同。内网需要能访问公网后台的 HTTPS 根地址，无需让公网访问内网。
2. 在两端分别配置、发布考试，导入相同的考号、账号密码、考生资料和题目。开始/结束时间、赛制、团队账号模式、冻结规则、题目顺序、题面、配置和分值必须一致。Hydro 题库编号、实例和域可以不同，检查通过后按考试题目顺序保存两端题号映射；考室、座位、监考老师、摄像头及登录 IP 设置独立管理。
3. 公网进入“考试详情 → 考试管理 → 跨网同步”，点击“生成同步密钥并开启接收”。复制本次显示的考试专用 API-KEY。刷新页面后不会再次显示已保存密钥；遗失时重新生成。
4. 内网进入同一设置页，填入公网后台地址、公网考试编号和 API-KEY。先“检查两端一致性”，再“保存并开启双向同步”。如果本地编号不同，只有尚无提交、登录会话或登录请求时允许自动对齐，且不能占用其他本地考试编号。
5. 页面展示同步开关、最近成功时间、错误和记录数量。公网轮换密钥后，所有内网节点要重新填入新密钥并保存连接；同一公网节点的历史进度保留。

账号核对使用以该考试密钥计算的摘要，不传输账号密码明文。题目核对包含顺序、题面、题型、判题配置、语言、时间与内存限制和分值的摘要；不因 Hydro 实例分配了不同题库编号而拒绝连接。此功能不会复制 Hydro 题库及测试数据文件；管理员须在各 Hydro 实例事先准备相同题目和测试数据。无法仅通过代码核对证明两台判题机的运行环境一致。

例如内网第 1、2 题的 Hydro 编号为 `71、73`，公网对应编号为 `10、12`：两端题目定义一致时保存 `71 → 10、73 → 12` 的映射。线上交换统一使用公网编号，提交在各端关联本地考试题目；内网重测仍送往本机的 `71、73`，公网重测使用本机的 `10、12`。两端后台都需升级到支持题号映射的版本。已有同步提交的映射不允许重新绑定为其他题号，避免修改原始提交的题目身份。

## 同步内容和重测

- 同步原始提交编号、考试编号对应的考号、题号、源代码、语言、原始提交时间、状态、原始分数、测试点、子任务、耗时、内存和人工评分。
- 公网汇总所有节点提交；内网也拉取公网汇总后的记录。所有节点按现有相同的计分和封榜规则计算排行榜。团队代表账号按考号确定，避免两端数据库创建顺序不同导致代表账号不一致。
- 公网可手动重测内网代码，内网也可手动重测公网代码，使用操作服务器自己的 HydroOJ 和对应题号。现有“所有递交”中的单条/批量重测入口继续有效，人工评分及取消成绩也参与同步。
- 收到提交时不会自动再次送判。手动重测产生的本机 Hydro 记录仅由本机轮询；远端 Hydro 记录编号不会安装到本机，避免串查其他判题实例的记录。
- 原始代码、考号、题目和创建时间不可随重测改变。重测更新同一条提交，不生成第二份提交。代码查重、导出及现有历史查询可以读取合并后的代码。
- 公告、指定考号公告、提问、完整追问与回复、公开状态及系统上传的答疑图片也支持双向同步，在任意一端回复均可。使用独立内容进度并逐条去重，已读回执留在本机，详情及后续升级 SQL 见 [公告答疑双向同步与并发复查](公告答疑双向同步与并发复查.md)。
- 手动重测在本机持久排队，接口先返回已入队，再由后台判题任务更新结果。重复操作跳过已排队记录；不会将入队数量显示为重测完成数量。

后台每 2 秒调度同步，判题状态由现有任务更新后进入下一批；网络正常且没有积压时通常数秒可见，不承诺固定两秒内完成。每次最多处理两场考试，每批最多 8 条，每场每轮最多整理 32 条及交换 4 批；大量历史记录会分批补齐。网络错误自动退避，最大约一分钟再重试，也可手动立即重试。

## 重复、冲突和恢复规则

- 全局身份是考试本地 ID、原始节点标识和原始提交编号；同步副本继续使用原始提交编号作为主键，冲突时拒绝覆盖另一来源。考生与题目 ID 在两端可不同，通过考号、题目顺序及已保存的两端 Hydro 题号映射。
- 每条提交只有一个最新快照，同步历史不因重试持续新增提交。版本由递增逻辑计数器和执行修改的节点标识共同决定。已观察到的版本之后修改必然得到更高版本；双方离线并发修改时，计数器较高者优先，相同计数器按稳定节点标识决定。此规则表示因果版本顺序，不以两台机器的墙上时间判定谁最后点击。
- 同版本同内容重发直接忽略；同版本不同内容报错；较低版本不能覆盖较高版本。接收前锁定提交并整理尚未发送的本地修改，防止新判题结果被旧请求覆盖。
- 推送和拉取使用数据库中的递增流序号。更新快照与增加序号在考试锁内同一事务提交；记录合并与接收方进度也在同一事务提交。响应丢失会重发，事务回滚不会跳过进度。
- 本地修改及游标持久保存在数据库。断网、后台崩溃或服务器重启后自动续传；未到期的任务租约最多等待约一分钟回收，不依赖进程内存恢复。
- 同步采用最终一致性，断网时两端榜单可能暂时不同。并发修改冲突收敛后，以选定的较高版本为准，需要其他结果时可在同步完成后再次手动重测。
- 节点标识和历史必须随完整数据库一起备份。禁止复制运行中节点数据库后把副本作为另一考试节点运行；提交编号和来源冲突会报错。不能只恢复部分表或把游标重置来强行合并不同历史。恢复较旧备份可能触发进度越界，应由管理员核对完整备份后处理。
- 开启同步后锁定考试定义、题目和考生资料，避免两端静默漂移；考室管理仍可单独修改。有同步记录后，即使暂停，也保留定义限制，因为当前协议不传播删除和重新编号。暂停不删除两端已收到的记录，已被远端接收的在途批次无法撤回。

## 接口和资源限制

- `POST /api/exam-sync/{10位考试编号}`：`Authorization: Bearer <该考试API-KEY>`，协议版本 1；支持 `manifest`、提交 `exchange` 和内容 `communications`。
- `GET/POST /api/exams/{id}/federation`：仅该场考试管理者，写操作沿用同源校验；专门生成密钥时一次返回密钥，普通读取只返回是否配置。
- 网络请求不跟随重定向；仅允许 HTTPS 根地址，本机开发可使用 localhost 的 HTTP。鉴权先于大请求体解析，收发上限各 16 MiB，每批最多 8 条，请求超时 18 秒。
- 同步使用单独的进程级队列和数据库任务租约，最多两个入站交换并发，不占用登录队列；网络请求不持有数据库事务。待整理记录按更新时间从早到晚处理，避免经常变化的老记录阻塞其他提交。推送按写入节点和序号索引读取，跳过无需回传的远端副本，不反复读取其代码。
- API-KEY 哈希用于验证，实际密钥使用基于本机 `SESSION_SECRET` 的 AES-256-GCM 加密保存。普通考试接口不返回密钥、哈希或密文；更换 `SESSION_SECRET` 后需重新配置同步密钥。
- 连接和每批交换核对服务器时间，偏差超过一分钟会提示校准。两端需保持时间同步。

## 数据库升级和发布

新增 `ExamFederation`、`ExamFederationEntry` 两张表，以及提交来源、待同步标记、逻辑版本和索引。既有提交保留，默认尚未整理，仅配置同步的考试会被扫描。不修改考生客户端表结构和安装包版本。

后续公告答疑功能另有内容流、图片及并发保护结构，须同时完成 [对应升级](公告答疑双向同步与并发复查.md#数据库升级)。下面的原始提交同步 SQL 不包含这些后续字段。

2026-11-05 的题号映射修复另需执行一次 [增量 SQL](../deployment/migrations/20261105-federation-problem-mapping.sql)，新增本地定义摘要和题号映射两列。旧连接、提交快照和进度保留原值，同题号连接继续兼容；已连接的考试无需重新生成密钥。内网新建连接时保存映射和独立的本地定义摘要，暂停后恢复仍核对本地完整配置。

可使用项目现有的 `pnpm --filter @cwnupaa/proctor-web db:push` 流程；也提供仅本次增量的 [SQL](../deployment/migrations/20261104-exam-federation.sql)，二者择一，先备份数据库。SQL 从本次修改前的 Prisma schema 离线生成，不包含删除旧列、清空记录或修改旧成绩；不是可重复执行的脚本。大表添加索引可能产生数据库负载，应安排发布窗口。

更新两端后台后再启用功能。升级期间未配置同步的考试继续走现有流程。代码回滚前先暂停同步，保留新增表列，不删除历史数据。旧版代码不会维护同步版本标记，恢复新版本前需核对回滚期间的提交和重测变化。此文档不代表已在生产环境执行升级。

## 本轮核对范围

遵循只检查代码的要求，未启动本地考试、同步联调或压力测试。执行 Prisma 客户端生成、TypeScript 静态检查及差异检查；增量 SQL 通过 schema 差异生成，未连接数据库执行。功能仍需在发布后的受控环境进行双端真实联通验收，不能以静态检查代替运行稳定性证明。

后台同时调整：移除全局“考试监考”导航，入口位于考试详情右侧“考试管理”下方；旧导航地址跳回考试列表。考试列表支持名称搜索，未结束考试按距离开始时间最近的优先，已结束考试置后，结束组内最近结束的优先。

# 直播流使用说明

本功能复用监考客户端已经发布的电脑屏幕、电脑前置摄像头和第二机位画面，不需要增加推流地址或重新推流。直播 API Key 与评测、协会官网、NovaJudge 等密钥分别管理，用于读取所有考试的监考直播，以及独立转发直播的 WebRTC 推流和播放；不授予监考客户端发布或后台管理权限。

## 生成和管理 API Key

1. 使用超级管理员账号打开监考后台的 **系统设置 → 直播 API Key 管理**。
2. 填写密钥名称，例如“比赛直播平台”，选择是否启用，点击“生成直播 API Key”。可以生成多个密钥，每个密钥可独立命名、启用、停用和删除。
3. 新密钥会加密保存，之后可在密钥列表点击“再次复制 API Key”。普通列表仅显示前缀，不包含密钥明文。升级前仅保存摘要的旧密钥无法还原，如需再次复制请新建密钥。
4. 不需要配置或绑定考试。观看指定考生时，在下述地址中填写目标考试编号、考号和机位；转发直播的链接由直播管理页显示。

启用的直播密钥可以读取本服务器上所有考试的可用机位，因此应只交给获准接入直播的系统。内网和公网各自管理自己的密钥，在其中一台生成的密钥不会自动同步到另一台。

## 直播地址

```text
https://监考后台域名/api/考试编号/考号/机位/apikey=直播API_KEY
```

- **考试编号**：考试管理页面显示的 10 位编号，例如 `2026101301`。不是数据库 ID，也不是 NovaJudge 比赛 ID。
- **考号**：本场监考考试中导入的考生考号。含特殊字符时对这一段进行 URL 编码。
- **机位**：`1` 为电脑屏幕，`2` 为电脑前置摄像头，`3` 为第二机位。
- **直播 API Key**：使用本服务器生成、已启用的完整 `live_…` 密钥。

公网例子，替换考试编号、考号和密钥后使用：

```text
https://proctoring.example.org/api/2026101301/20260001/1/apikey=直播API_KEY
https://proctoring.example.org/api/2026101301/20260001/2/apikey=直播API_KEY
https://proctoring.example.org/api/2026101301/20260001/3/apikey=直播API_KEY
```

内网将域名换成 `proctoring.example.test`。同时支持查询参数形式：

```text
https://proctoring.example.test/api/2026101301/20260001/1?apikey=直播API_KEY
```

## 播放和接入

直播入口与后台视频监考均使用 **WebRTC**，直接复用客户端发布的画面。入口地址使用浏览器打开后显示直播播放器，也可以用于 OBS 的“浏览器”来源。播放过程中不使用 HLS 分片，不需要重新推流。

需要自己集成播放器时，使用同一个入口地址作为 WHEP 信令接口：

1. `POST` 入口地址，`Content-Type: application/sdp`，请求体为接收端 SDP offer。
2. 服务器返回 `201` 和 SDP answer，将 answer 设置到接收端。响应的 `Location` 是这条观看连接的后续地址；只使用服务器返回的地址，不拼接内部媒体地址。
3. `PATCH Location`，`Content-Type: application/trickle-ice-sdpfrag`，`If-Match: *`，发送后续 ICE 候选地址。此步骤用于持续补齐网络地址，避免部分浏览器或网卡较慢时连接失败。
4. 停止观看时 `DELETE Location` 释放连接。

后台提供的 `/live-webrtc.js` 中有 `createProctorWebRtcReader`，后台监考与默认直播网页共同使用该连接逻辑。接口支持跨域信令，接入端不会获得内部媒体签名密钥、监考登录凭据或推流权限。

密钥错误、停用或删除后，新连接和后续信令请求立即被拒绝。停用或删除密钥时，后台也会主动断开属于该密钥的已建立 WebRTC 观看连接；不会断开考生的推流或监考老师的后台观看连接。媒体服务暂时不可用时，密钥保持停用，并提示重试断开连接。

考生更换会话后，旧观看资源不会切换到另一条会话。播放器从固定入口重新连接，读取该考号最新的有效会话。已结束或撤销的会话、考室未启用的机位不可新建观看连接。

## 网络要求

观看设备必须能到达本服务器的 WebRTC 地址。内网 `proctorrtc.example.test` 必须解析到 `192.168.50.20`；公网使用公网服务器自己的域名解析。公网使用 TCP/UDP `443`。内网 Chrome 观看使用 TCP/UDP `18189`，由内网网关转发到原媒体服务；原 `443` 入口继续保留，已连接的客户端无需断开。内网 `deployment/docker-compose.host.yml` 的 web 环境中设置 `MEDIA_BROWSER_ICE_PORT: "18189"`，网关转发参考 `deployment/Caddyfile.intranet-ice.example`。防火墙只向考试局域网放行这个端口。不能复制另一台服务器的端口设置。

Chrome 会拒绝“私有 IP + 80/443”形式的 ICE 地址，因此内网不能直接把 `192.168.50.20:443` 作为浏览器观看地址。端口映射只调整 ICE 地址，不改变 SDP 凭据、证书指纹或鉴权；公网未设置此内网覆盖时，其连接地址保持原样。

浏览器、系统防火墙或 VPN 若阻止局域网实时通信，会导致网页可以打开而 WebRTC 画面无法连接。应允许监考站点访问所需网络，确认局域网解析和端口连通；不需要关闭证书校验。

## 常见响应

| 状态码 | 含义与处理 |
| --- | --- |
| `200` | 浏览器直播观看页。 |
| `201` | WebRTC SDP 协商成功。 |
| `204` | 候选地址交换、连接释放或授权检查成功。 |
| `400` | 考试编号、考号、机位、SDP 或连接资源格式错误。 |
| `401` | 直播 API Key 缺失、错误、停用或已删除。 |
| `403` | 观看资源不属于当前密钥、考生会话或机位。 |
| `404` | 无有效会话、机位未启用、尚未推流或观看资源已失效。 |
| `415` | SDP 或候选地址的请求内容类型不正确。 |
| `502` | 媒体服务连接或协商失败。 |

密钥管理接口只允许超级管理员访问：`GET/POST/PATCH/DELETE /api/settings/live-api-keys`。创建返回一次完整密钥；列表、名称修改和启停响应不会返回完整密钥或其散列。

独立的 WHIP 推流和 WebRTC 转发播放见 [直播接收与转发使用文档](直播接收与转发使用文档.md)，共用本页系统设置中的密钥。

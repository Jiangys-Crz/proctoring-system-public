# 公告答疑双向同步与并发复查

本次扩展适用于已配置跨网同步的 HYDRO 本机考试。沿用该考试的 API-KEY，通过考试编号和考号匹配；NovaJudge 和公开环境测试不启用。内网主动推送并拉取，公网无需访问内网。只更新监考后台、服务端和数据库，无须修改或更新考生客户端。

## 可以同步什么

- 全体公告、指定考号的公告，以及提问、完整讨论中的每条追问和老师回复。
- 在公网或内网查看同一问题并回复均可，回复在本机保存后分批传到其他节点。原有考室权限继续生效；同步不会授予其他考室的访问权限。
- 公开提问和取消公开。每次重新公开使用新的公开批次，防止上次公开生成的公告在补传后重新出现。
- 原始创建时间、原始消息编号、回复老师的显示名称，以及通过本系统上传的答疑 WebP 图片。远端老师不需要在接收端创建同名管理员账号。

公告确认已读和回复确认已读仍属于本机，不跨网传播。会话、登录凭据、监考权限、考室设置和监考视频不进入答疑同步流。普通外站图片链接保留原链接，本系统不主动抓取外站图片。

## 配置和使用

1. 先完成 [公网内网考试双向同步](公网内网考试双向同步.md) 的题目、账号、考试规则及 API-KEY 配置。
2. 公网、内网均升级到本次版本及数据库结构。已有连接沿用原密钥和提交进度，新增答疑进度从零补齐；新建连接会检查公网是否支持公告答疑和图片同步。
3. 在任意一端的“考试详情 → 赛时答疑”发布公告、回复或调整公开状态。无需再设置第二个开关。
4. 在“考试管理 → 跨网同步”查看提交同步与公告答疑各自的最近成功时间、错误信息。连接正常且无积压时通常数秒到达；断网、图片存储故障或历史补传期间会延迟。
5. 恢复连接后自动按数据库进度补传，也可点击立即重试。不要通过清空同步表或重置进度解决冲突。

既有历史问题、消息和公告也参与补传。旧版只有问题和单条答案、尚无消息行的记录，会使用固定消息编号补齐讨论，避免两端各造一份旧回复。旧记录保留原时间，收到远端的新公告和回复使用本机接收时间触发通知，避免因原时间过早而漏推。

取消公开会在同步到达后停止后续公开查询，并隐藏与该公开批次关联的公告。已经显示在旧客户端弹窗、浏览器缓存或已复制出去的内容无法远程收回。升级前生成、没有关联问题编号的独立历史公告也无法自动认定为某次公开的附属公告。

## 重复、并发及断线规则

- 每条消息和公告沿用源节点的固定编号；同编号同内容重发直接忽略，不生成第二条记录。同编号不同内容、不同来源或不同考试直接拒绝，避免静默覆盖。
- 回复逐条合并。两端离线时同时回复会保留两条，不能用单个 `answer` 字段相互覆盖。问题列表中的答案摘要从完整消息重新计算。
- 同一问题的本地写操作使用行锁。讨论采用单调逻辑顺序和稳定编号排序，回复已观察到的消息会排在它之后；两端同时写入、互相尚未看见的消息按稳定顺序显示。原始时间仍单独保留。
- 公开状态使用递增版本和节点标识解决同时修改；已观察到的版本之后操作会得到更高版本。版本相同时按节点标识收敛，不依赖谁的机器时间更快。
- 内容快照与流序号同事务写入；接收内容与推进游标同事务提交。响应丢失可以重发，服务重启从持久进度继续，残留租约约一分钟后回收。
- API-KEY 的持有端是受信任的考试节点。每个节点使用自己的唯一标识，完整数据库连同同步历史一起备份；不要复制正在使用的数据库并把副本当作新节点。

## 图片与性能边界

- 每轮最多读取一张新的本机图片，读取本机文件或已配置的对象存储，不根据消息中的任意地址请求网络。图片读取、校验、编码和远程请求都在考试事务之外。
- 图片限有效 WebP、单张 10 MiB、宽高各不超过 10000。校验大小、摘要和类型；一个传输包中的图片总量最多 10 MiB，每批最多 8 项，整体请求和响应仍受 16 MiB 限制。
- 图片以独立数据记录保存，不在每个回复快照里重复存储。接收端返回本机图片地址，可不依赖源节点继续显示图片；图片地址使用独立随机访问密钥，有效期为生成后 90 天，不能将该链接视作可公开转发的无权限资源。
- 图片读取有独立并发和等待上限，输出分块并随断开释放占用。同步队列与登录队列分开；内容出站任务在每个进程内最多一个，内容入站合并在每个进程内最多一个。
- 图片读取失败时相关内容保留待同步标记并轮换重试，其他记录可继续整理。答疑错误单独显示、单独退避，不会因答疑图片不可读而停止提交成绩同步。
- 后台答疑轮询同一页面串行处理，慢的旧请求不能覆盖发布、回复后的较新状态。
- 同一公告引起大量考生同时刷新时，答疑查询也使用独立有界队列，最多四个并发读取；回复和确认写入最多两个并发，超出等待上限返回可重试的繁忙提示，避免无限堆积数据库请求。

以上限制用于约束资源占用，不能代替服务器真实容量测量。断网时两端暂时不同，采用最终一致性。

## 本次同时修复的并发问题

- 单条、批量重测改为持久排队，接口不再加载全部代码并等待逐个远程判题完成。重复点击跳过已排队记录，人工评分保留；后台页面提示已入队，后续状态查询显示实际结果。
- 判题发送、结果轮询、手工评分、成绩取消及远端导入使用写入标识保护。旧判题请求的迟到结果不能覆盖取消或新的操作；人工评分在事务中确认该记录仍为本题最后一次有效递交，已变化时返回冲突提示。
- 判题状态共享正在进行的请求，避免不同后台入口重复拉取同一记录。
- 直播密钥数量上限放入锁内核对，防止同时创建突破上限；管理操作加锁后读取最新禁用、归档状态；播放票据拒绝多余分隔段。
- 同步摘要限制深度、节点数和大小，远端错误隐藏考试密钥，导入核对考号和记录编号的精确大小写。

## 后续复查：断网补传、未读恢复和排行榜

本轮以 `44c8be1` 为基线继续核对，仅修改后台、服务端及数据库。

- **两类同步分别重试。** 提交同步与公告答疑使用独立的下次尝试时间。单条提交异常或提交接口故障时，仍会尝试公告答疑；答疑图片故障也不阻断提交。仍共用考试租约，每个有界数据库阶段核对并续租，旧任务不能续租或释放其他任务的租约。网络请求继续在事务外执行。
- **未读内容优先恢复。** 考生答疑接口仍最多返回 50 个讨论、50 条公告，优先返回本人有未读老师回复的讨论和本人未确认的有效公告，再补最近内容。确认后下一轮继续返回剩余未读批次，避免较早的补传记录被最新 50 条永久挤掉。讨论按最近更新时间排列，旧讨论收到新回复也能出现；不会把其他考生的私有讨论加入未读列表。
- **图片故障只占一次读取。** 每次准备最多尝试读取一张新图片，包括失败尝试。故障文件在当前进程内退避约 30 秒，让后续正常图片继续处理；待同步标记仍在数据库中，重启后可以重新尝试，不会因为退避而跳过记录。失败缓存有数量和时限上限。
- **图片元数据批量查询。** 同一批 Markdown 引用先去重，再批量查询已有图片，避免每个链接各查一次数据库。普通外站链接不会因为路径恰好含有本场 `qa/` 字样而被误认成未准备完成的本机文件。以 `//` 开头的外站地址作为完整 URL 处理，避免替换其路径部分时把本机图片访问密钥拼到外站地址上。
- **榜单顺序固定。** 同分的展示顺序和同一时刻提交的选取，使用固定字符串顺序，避免依赖服务器默认语言环境。团队成员和参赛分组一次建立映射，减少逐队、逐组扫描完整名单；同进程中重叠的榜单读取共享正在进行的查询，完成后不缓存旧结果。

继续核对了响应丢失后重发、同版本重复接收、两端同时回复及图片跨批到达的路径：沿用固定消息/提交编号和事务游标；回复仍逐条追加，公开状态仍按版本收敛，不按单个答案字段相互覆盖。该结论来自代码检查，未进行运行联调。

## 再次复查：原始快照、等待顺序与评卷一致性

以下修复以 `30e3a61` 为基线，不再增加数据库字段，不修改客户端。

- **公开状态不改写原文。** 提问已经产生同步快照后，修改公开状态会复用该快照中的原始文字、图片引用、初始消息编号和原始时间，只更新公开状态、消息时钟和版本。避免图片地址处理规则升级或存储地址改变后，把同一问题误判为原始内容被修改。

- **较早未读内容优先补齐。** 未读讨论和公告先返回较早批次，再补最近内容；确认后继续读取下一批。避免新公告持续进入时，较早未读记录一直挤不到前 50 条。新发的监考警告也记录实际投递时间，旧数据仍保持原有时间回退规则。

## 排队上限与旧会话补齐复查

以 `0b938ec` 为基线继续复查，本轮没有新增数据库字段或客户端改动。

- **满队列可以回收失效名额。** 新考试遇到 128 个等待标记的上限时，会先批量核对已有等待者，清理已删除、暂停、重新配置、暂未到重试时间及由其他进程接管的标记，再尝试加入。避免旧考试不再执行清理、导致新考试永远无法入队。异步核对后仍比较标记对象，防止误删期间新建的等待位置；执行槽的并发上限保持一个。
- **接收图片引用批量核对。** 每个接收批次先提取并去重图片编号，一次读取本场考试已有的图片访问摘要，重复引用使用本批次内的校验结果，减少持有考试锁期间的重复查询。同批新图片必须已经写入当前事务，后续正文才能引用；不会仅凭图片声明放行。缺少图片数据、引用不存在或访问密钥不符时，事务回滚，接收进度不前移。
- **旧会话先识别真正首问。** 未初始化的旧讨论按原始文字精确寻找首问，不再把第一条追问直接当成首问。缺少首问时补入固定编号的原始提问；已有相同原文的老师回复不再重复补造旧答案，缺失且内容不同的旧答案使用内容相关的固定编号保留。初始化会覆盖所有尚无排序时钟的旧消息，并保证首问排在补齐的追问、回复之前，原始创建时间保持不变。
- **不静默覆盖不一致历史。** 如果既有首问身份与原文已不一致，会提示核对历史记录并保留原消息，阻止用首问内容覆盖实际追问。这属于历史数据完整性保护，不会猜测修改已同步记录的身份。

旧答案的原文核对仅用于兼容初始化。正常回复仍按各自固定编号逐条同步，两端发送相同文字的两条正常回复会分别保留。继续核对了排行榜的固定排序、评卷最后一次递交选择、重复接收及断网游标恢复，未改变这些规则。

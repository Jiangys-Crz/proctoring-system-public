# 客户端 1.0.10：实时通话与监看声音

## 使用行为

- 监考页面点击“语音通话”后呼叫该考生的电脑客户端。客户端显示来电，考生可以接听、拒接；接听后双方实时说话，可静音或挂断，不再使用“录完再发送”的方式。
- 通话对象在拨号时固定。切换监看考生不会把正在进行的电话转给其他人；同一监考员、同一客户端均只能参加一通电话。
- 单人监看默认播放当前考生电脑麦克风的声音，翻页后释放上一人的播放连接；电脑没有摄像头也能采集麦克风。前置摄像头不再重复采集声音，四人监看静音。
- 电话期间暂停监看声音，避免电话和监看声音重叠；挂断后恢复当前画面对应考生的声音。浏览器阻止自动播放时显示点击播放按钮。
- 电脑录音源由监看和电话各自使用独立音轨。电话静音、挂断不会关闭屏幕推流的麦克风；麦克风恢复后重新接入推流与已启用的录像。
- 无麦克风或权限不足时提示设备问题，不因没有摄像头而阻断麦克风。语音模块不会生成 USB 插拔告警。
- 本版包含 1.0.9 的 Windows 7 USB 物理设备核实、防抖及 `usb-v6` 基线迁移修复，详见前一版说明。

## 录像保存检查

已核对桌面端、手机网页、原生手机推流及后台上传入口。**“保存完整录像”和“保存异常录像”都关闭时，不新增监考录像。**

桌面端和手机网页不启动监考录像编码器；收到关闭设置后停止已有编码器并清空内存证据缓冲。后台独立检查考试设置，即使旧客户端继续上传，也直接丢弃电脑屏幕、电脑摄像头、手机摄像头及旧版视频证据通道的视频，不建立文件和录像记录。上传途中关闭开关的竞争情况会清理已写入但未纳入录像目录的文件。MediaMTX 的直播、环境测试与通话路径均关闭服务端录像。

关闭开关不会删除此前已保存的录像。考前身份照片、环境视频、异常截图及独立的旧版手机语音消息仍按各自功能保存。新实时通话不生成语音消息文件，仅保存通话状态；已开启的屏幕录像仍按考试配置包含电脑麦克风音轨。进行中修改录像选项需要客户端收到下一次心跳响应后停止本地录制，后台上传拦截立即按当前设置生效。

## 验证结果

- 桌面构建、273 项测试通过；后台生产构建和类型检查通过，语音及相关权限/生命周期 45 项测试、告警 52 项测试、手机网页录制 8 项测试通过。
- 隔离 MySQL、Next、MediaMTX 与真实 Chrome 验证双向声音（约 220 Hz / 880 Hz 合成音）、静音、挂断、媒体控制接口资源释放、12 路并发拨号唯一性、凭据与通话对象隔离、超时及会话撤销。实时通话没有新增旧版语音文件。
- 使用客户端同版本的 Electron 22.3.27 / Chromium 108 实际推送 H.264 + Opus，在无摄像头的合成场景中验证屏幕录像确实含声音；后台听到甲、乙考生的约 330 Hz / 660 Hz 声音，翻页、四人静音、固定通话对象及挂断后恢复当前考生声音均通过。
- 独立 `proctor_recording_qa` 数据库及临时本地文件目录验证：录像默认关闭、两个选项关闭时零录像记录及零视频文件、异常录像仅匹配对应通道/时间窗口、重复上传去重、进行中关闭开关及上传竞争后的文件清理。
- Windows 安装包 `proctor-1.0.10-unified-windows-setup.exe`，224,995,226 字节；从实际安装包解出 x64 / ia32 载荷，各核对 55 个应用文件、4 个原生组件及 FFmpeg。SHA-256：`3139620047c205f3d45f23ebe0c0503eed1330bcac81b596f54a3edc95af2ddc`。完整记录见同目录 `release-manifest-1.0.10.json`。

测试仅使用合成画面和声音，没有读取真实考生音视频或操作生产数据库。本机没有 Windows 7 真机；原误锁机器仍需安装新版后复测，并检查实际声卡/麦克风驱动。

## 更新部署

1. 在维护时段更新后台，执行 `pnpm --filter @cwnupaa/proctor-web db:push` 建立 `VoiceCall`、`VoiceCallConnection` 表，再重新构建和重启后台。Docker 的现有后台启动流程会执行数据库更新。
2. 同步并重启媒体服务，应用 `apps/media/mediamtx.yml` 或 `mediamtx.caddy.yml` 的 `voice/` 路径配置。继续使用既有私有媒体控制接口和 WebRTC 网络端口，不向公网开放 9997。
3. 发布并安装 Windows 1.0.10，重新登录。实时通话和电脑麦克风推流需要新版客户端；仅更新网页无法替换旧客户端逻辑。

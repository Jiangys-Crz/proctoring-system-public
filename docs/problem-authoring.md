# 题库创建

题库管理右上角的「创建题目」支持客观题题组和编程题。沿用现有超级管理员权限、系统设置中的 Hydro 连接及专用题库域；浏览器不能自行指定其他域或取得 Hydro API Key。后台与两端 Hydro 必须更新本次插件整个目录，包含 `problem-bank.ts`、`problem-authoring.ts` 和已有辅助文件。无需新增 SQL 表。

## 客观题

一个题组只创建一个 Hydro 题目，类型为 `objective`。小题及选项在编辑期间使用独立标识；输出时按当前顺序生成数字控件编号和 A～Z 选项答案。判断题转为「正确／错误」两个选项的单选题。删选项同时移除其答案引用；后端再次校验，不接受悬空答案。

原始编辑内容随创建恢复记录保存在 Hydro 的私有 `proctor.problem.creations` 集合。题面由原始 Markdown 组合，作答控件位于题干之后、选项列表之前。题面和预览不拼入标准答案，答案只进入后台 `config.yaml`。描述及选项支持代码块、公式、列表和表格；未闭合的客观题代码块会阻止保存，避免吞掉后续作答控件。

计分核对依据为当前工作区 HydroOJ `5.0.0-beta.18`、Hydrojudge `3.5.0-beta.14` 的 `judge/objective.ts` 和题面控件源码：

- 单选、判断、填空：完整匹配得该小题分值，否则 0 分；未答 0 分。
- 多选：可按小题设置「有部分分」或「无部分分」。全部选对得满分；启用部分分时，漏选且无错选得小题分值的一半，例如 5 分题得 2.50 分。无部分分时，漏选得 0 分。错选或未作答得 0 分。
- Hydrojudge 原生版本会把部分分向下取整。部署时需在负责判题的 Hydro 源码或安装包中应用 [多选部分分补丁](../hydro-plugin/hydrojudge-objective-half-score.patch) 并重启评测进程。源码检出在仓库根目录用 `patch -p1`，已安装的 `@hydrooj/hydrojudge` 在包根目录用 `patch -p3`，均将补丁文件作为标准输入。
- 填空：去除考生答案首尾空白，内部空白不改变，区分大小写，完整字符串精确匹配。不提供正则、多候选答案或忽略大小写选项。标准答案若含首尾空白会明确报错，不替用户修改。
- 标准配置和考生答案均用 JSON 文档序列化；JSON 是 Hydro 使用的 YAML 读取器可识别的格式，字符串 `0`、`true`、冒号、引号、反斜杠、`#` 和多选数组不会发生隐式类型转换。学生历史 YAML 答案继续兼容读取。

每小题／测试点为 1～100 的整数分，遵守当前 Hydro 配置编辑器的单项范围；总分直接相加，不压缩到 100。保留考试系统 100000 分总上限。最多 200 个小题／测试点，全部创建内容的 JSON 不超过 6 MiB，界面与后端均给出校验提示。

## 编程题

默认时间 1000 ms、内存 256 MiB，可在表单修改。公开样例由作者写入 Markdown 的 `input1`／`output1` 代码块等位置；后台测试点不自动成为样例。

第 N 个测试点对应 `N.in`、`N.out`，配置为一个独立 `sum` 子任务，子任务和唯一测试点均显式填写该点分值。采用 Hydro 默认比较器。不同分值例如 20、30、50 分会原样分别写入配置，各点独立计分后求和。输入及输出按 UTF-8 原文写入，不调用 `trim`、不补换行、不去除空行或缩进；空字符串须分别勾选空输入／空输出确认。

测试文件与配置仅放入 Hydro 的 `testdata`，不进入公开附件。题目读取接口继续移除客观题 `answers`，也不返回后台文件的 ETag、大小等可用于猜测答案的指纹，公开下载接口仅允许公开附件；带答案的题库同步接口仍要求服务端密钥，创建接口仍要求超级管理员及可信请求来源。

## 保存、重试与同步

浏览器保存期间阻止重复点击；固定创建编号及内容后，后续请求只传编号继续。首次请求和失败重试可携带原内容，修改后的内容不能复用旧编号覆盖。监考数据库 `SystemSetting` 的 `problem-create:` 记录绑定创建者、内容摘要、原 Hydro 连接和域；插件的私有恢复记录保存原始草稿及文件进度。

Hydro 初次插入题目时就写入创建标识，避免插入后进程退出导致重试再建题。每步最多写入两份文件，已保存部分复用；中断后还会补齐文件登记和配置更新。所有文件、题面和配置一致，并通过 Hydro 原生配置解析与题数核对后，才原子移除未完成标记并记录完成身份。监考端保存数字编号及 Mongo 原生文档身份，后续重试再次核对；进度回写只会从待保存前进到完成，不会被晚到的旧响应退回。完成响应丢失后重试返回同一原题；原题后来被编辑时不会回放旧草稿，对于已经记录原生身份的创建，原题已删除或数据库被替换时停止，不重新建题。

未完成题目从列表、详情、导入读取、判题及同步目录中排除，普通原生编辑等待其恢复完成。恢复记录不会被标记为创建成功。窗口关闭和网页离开均提示未保存状态；同页重新打开窗口可继续原输入和保存。离开页面后可由有权限的运维人员依据两端恢复编号核对并恢复私有创建记录；本功能不将答案和测试数据写入浏览器长期存储。

完成后自动返回 Hydro 内部数字 `docId`，刷新题库并提供查看链接。已开启公网／内网题库同步时，由现有扫描、身份映射、文件清单校验和分步补传流程接续，答案配置及测试文件一起同步。只有当前配置的专用域参与，其他域不受影响；同步关闭时不会擅自开启。

## 本次代码核对

后续代码复查将已有文件复用检查、最终校验也改为可恢复批次：每阶段每次最多检查 16 份文件，并设置时间预算，实际写入每次最多两份。校验未齐不会完成创建，重写文件会回退相应校验进度。原生创建上下文跨插件热重载共享；需要随两端后台一并更新 Hydro 插件。本轮复查未修改客户端组件。

再次核对补上了校验中途失败时的进度保存：后续文件读取或散列失败，不会丢弃同批此前已成功校验的进度；未完成文件继续等待重试，不提前完成创建。

| 场景 | 核对的实现路径 |
| --- | --- |
| 混合四种小题 | 一个创建标识只生成一个原生文档，所有小题进入同一 `answers` 配置 |
| 增删、排序 | 稳定编辑标识保留引用，按当前顺序同时生成控件、选项字母和答案键 |
| 正确、错误、未答、多选部分正确 | 对照上述 Hydro 判题分支；浏览器答案使用可安全解析的 JSON |
| Markdown 与特殊字符 | 复用现有 Markdown、GFM、数学预览；共享控件解析保留多行选项、嵌套列表及代码中的字面反斜杠 |
| 多测试点及不同分值 | 文件名与子任务引用来自同一次顺序遍历，显式分值不自动分摊 |
| 答案及测试数据隔离 | 创建权限、固定域、公开配置移除答案，私有测试目录及未完成状态过滤 |
| 失败重试及重复提交 | 双端持久化创建身份、内容固定、初次插入标记、文件进度和最终完成标记 |

按要求仅做源码核对，未运行本地测试、类型检查、构建、浏览器验证、服务或实际判题。上述工作区版本依据不等同于对线上运行版本的探测结论。

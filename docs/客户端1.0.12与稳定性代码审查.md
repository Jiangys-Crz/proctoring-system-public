# 客户端 1.0.12 与稳定性代码审查

日期：2026-11-04。

本次交付为代码修改和静态逻辑审查。用户在工作期间明确要求停止本地测试验证，因此最终修改未运行构建、压测、浏览器验证或真实 Windows/macOS 设备验证；未生成新的安装包，也未上传、发布或重启线上服务。源码版本由 1.0.11 调整为 1.0.12，不能据此认定下载站现有安装包已经更新。

## 会话与服务器恢复

按本次确认的规则：断线超过两分钟仍保留会话、令牌和首次开考时间；正常考试截止时间、手动结束和监考注销仍生效。后台健康扫描只标记离线，不再因心跳超时销毁会话，因此服务器重启后的原客户端可以使用原凭据恢复。

同一账号完成新的登录事务时，在同一事务中注销旧会话、清除电脑与手机令牌、作废旧配对和恢复凭据，再建立新会话。原考试计时保持不变。登录不成功或事务回滚不会提前注销旧会话。账号重新登录仍需满足现有考试时间、身份、考室、材料和 IP 限制。

新会话继承旧会话尚未解除的锁定，避免通过重新登录绕过监考处理。补充审核与解锁的状态判断：解除锁定不等于登录审核通过；未审核会话不能借 LOCKED 状态取得答题权限。旧会话异步返回的评测服务登录结果需要再次核对状态。

相关代码：`candidate-login.ts`、`session-revocation.ts`、`session-health.ts`、`session-health-scan.ts`、电脑/手机重连及配对接口、登录审核和解锁接口。

## 锁定和后台提示

- USB 枚举失败或结果过期仍上报告警，但不再将检测组件不可用直接等同于真实设备插拔并自动全屏锁定。真实 USB 事件、指纹变化和监考锁定保留原处理要求；已经存在的锁定仍由监考处理。
- 考试后台从当前有权限查看的考生会话生成锁定弹窗队列，包括当前分页、筛选条件之外的考生；显示考生、考号、座位和锁定原因，并提供填写原因后解锁。相同锁定事件不会随每次心跳重复弹出。
- 监考全屏展示到达本地预计结束时间时，先向服务器确认结束。断网、超时、错误响应不能解除展示；不再仅靠本地定时器解锁。
- Windows 全屏保护组件失败后持续按有上限的间隔重试，不再尝试三次后永久停止保护恢复。
- 若同账号新登录明确注销了旧会话，展示状态接口可确认该旧会话已经终止，避免旧电脑因令牌已清除而永远无法获得展示结束确认。活动会话的无效令牌和网络故障不能触发该分支。

## 权限检查和版本

原媒体检测仅凭系统摄像头授权标记判断可用，且 `mediaReady` 只取屏幕结果。测试后摄像头被占用、设备断开或麦克风不可用时，这个旧状态仍可能允许进入登录。

现在在生成正式登录配对前重新采集屏幕画面、摄像头画面及麦克风轨道，并释放探测流；设备实测有超时限制，迟到返回的流也会释放。服务器同时检查要求前置摄像头的考室是否具备对应检测结果。无有效会话时重新检查发布版本，避免客户端长期停留在先前的版本检查结果。

测试考试仍保留其体验模式，不保存正式监考记录；正式考试的时间、分配考室、登录方式、IP 绑定和监考审核仍可能阻止登录。没有受影响电脑的运行日志，无法把所有历史登录失败归为同一原因。

现有打包脚本已检查包内 `package.json` 版本，Mac 另外核对两个应用版本字段。本次没有重新打包，1.0.12 修改需要后续重新生成相应平台安装包并发布后才会到达考生电脑。

## 并发与下载

- 登录入口在读取请求体和占用数据库连接之前有界排队；默认每进程同时处理 8 个，最多等待 128 个，排队最长 8 秒。`LOGIN_MAX_CONCURRENT` 可配置，默认值不是实测容量。
- 会话写入除原有逐会话串行外，增加每进程最多 8 个并行事务、256 个等待请求的总限制。连接池/事务繁忙返回可重试响应。
- 登录及审核与心跳统一“先会话、后考生”的锁顺序，并保留必要的死锁重试；新登录再次读取会话，确保竞争登录最终只有一个有效会话。
- 自动签发及客户端主动获取评测服务登录凭证共享最多 4 个并行请求的限制。监考审核响应不再等待外部评测服务登录完成。
- 测试考试模板在启动时初始化，正常登录读取已初始化的考试，避免每名考生都锁住并重写同一考试及考室。
- 测试登录 multipart 接口绕过会复制请求体的代理层，由接口自身执行上传限流和大小检查。
- 浏览器和监考后台 JSON 请求增加超时与取消清理，防止断线后请求永久挂起；没有自动重试可能产生副作用的登录/提交操作。
- 安装包下载最多并行 64 条流，Node 文件流和 Web 流明确按字节限缓冲，保留背压。连接中止/流取消会释放文件句柄、监听器和并发计数。
- 下载补充 HEAD、ETag、If-Range、范围参数安全整数检查和文件句柄一致性检查；HEAD 不读取安装包正文，过期 If-Range 重新返回完整文件。安装包自动更新原有大小和 SHA-512 校验继续保留。

以上是从代码路径确定的风险及修复，不能替代真实服务器容量测量、现有安装包内容核验或客户端操作系统级验证，也不代表已证明服务器崩溃的唯一原因。

## 第二轮：环境检测与性能补充审查

同日按用户要求继续进行静态代码检查，仍未运行本地测试、编译、客户端实测或压测。本轮发现并修正以下额外路径：

| 代码中的风险 | 修改后的处理 |
| --- | --- |
| Windows 媒体权限返回 unknown 等状态时，实际采集成功也未被保存；而媒体检测按钮又被所有权限状态拦住 | 基础系统检查与媒体实测分开；保存本次设备实测结果，未知状态需要实测判定；明确拒绝授权仍拦截必需设备 |
| 不要求前置摄像头的考室也被客户端统一的摄像头检查拦住 | 客户端保留摄像头失败提示和真实检测结果；服务器按考室要求决定能否登录。系统测试及要求前置的考室仍必须通过摄像头实测，账号登录会在要求第二机位材料前提示该问题 |
| setCheck 覆盖具体失败信息，甚至用权限总状态覆盖虚拟机检查的失败结果 | 保留真实检查状态、检测中状态和具体原因，不再把基础权限已开等同于系统检查通过 |
| Windows 7 实际使用 GDI/FFmpeg 采集，但前置检查只走 Chromium | 前置检查改为验证同一个原生采集路径，并释放临时采集租约 |
| Mac 活动窗口识别依赖 System Events，原操作入口只引导辅助功能授权 | 补充自动化授权入口与具体提示，并保持活动窗口检测失败时的拦截 |
| Mac system_profiler 类型列表的缩进或未提供雷电检测类型会使外设检测始终失败 | 规范化类型列表，只请求系统声明支持的组件；声明支持的组件报告缺失、损坏时仍视为失败 |
| 虚拟机检测扫描整个硬件报告，序列号/UUID 或型号中偶然包含短字符串可能误判 | 使用厂商及型号字段；短标识 KVM/Xen 使用单词边界判断，不再检查序列号 |
| 屏幕采集启动 Promise 不返回就无法尝试其他方案；严格最低帧率及相同的两次回退无法解决低性能设备兼容性 | 给采集尝试加超时，验证首帧后接受流，超时后返回的流也会关闭；降低最低帧率约束，并提供不同的低帧率回退 |
| Renderer 网络探测没有超时，主进程与页面探测串行，某一路卡住会拖住整轮检查 | 页面请求含响应体读取均受超时限制；主进程与页面探测并行；系统组件/网络采集探测也有等待上限 |
| 权限卡片、窗口焦点刷新和登录按钮重叠执行，重复启动系统进程，旧结果可能覆盖新服务器状态 | 合并同时进行的刷新、进程枚举、能力检查和同一媒体设备探测；串行处理登录/检测按钮操作；结果提交前核对服务器和会话上下文 |
| Wireshark 已安装但组件损坏时，原逻辑不会尝试已有的系统备用方案 | 启动失败后尝试系统备用检测；基础模式在权限卡片中明确显示，保留原有基础模式准入规则 |
| 多台客户端各自同时使用多种网络传输检测健康状态，重复争抢数据库连接 | 仅合并进行中的数据库健康探测，不缓存已经完成的健康结论 |
| 客户端设备 ID 文件被中断写入而为空或截断后，所有配对都可能被参数校验拒绝 | 校验原有设备 ID，损坏时重新生成并原子写入。设备 ID 仍只是设备标签，不作为身份凭证 |

需要继续保留的正常失败情形：必需设备缺失或被占用、用户拒绝权限、系统检测组件被隔离或损坏、USB 报告确实不完整、服务器/证书不可达、实际虚拟机触发考试限制，以及考试时间、考室、版本、账号或 IP 限制不符合要求。对这些情况现在提供更具体的提示；静态审查不能证明所有机器都能通过，也不能代替现有安装包或线上服务器的实际核验。

另补充了 Node HTTP 备用请求的响应流 `error`/`aborted` 处理和 16 MiB 正文上限。原先只监听请求错误，服务器在返回响应头后崩溃可能使响应流错误逸出；现在按普通请求失败交给重连处理，避免这条路径意外终止客户端。

这些是代码路径上的修复，未测量真实并发容量或确认历史崩溃的根因；当前源码仍需要后续打包、发布才会到达考生电脑。本轮没有改变断联会话保留、同账号新登录注销旧会话和原开考计时规则。

## 第五轮：恢复响应丢失、换机退场和考试页高峰

继续仅核对和修改代码，没有运行本地测试、构建、设备实测、压测或部署。

| 代码中的遗漏 | 本轮修改 |

# 客户端 1.0.9：Windows 7 USB 误锁修复

本轮反馈为“Windows 7 电脑未接摄像头，客户端直接锁屏”。未取得故障机器当时的提示原文和日志，不能确认其现场唯一原因；以下修复针对代码中已经确认的误报路径。

## 修改

- USB 通知监听启动后先建立当前物理设备清单。重复的接入通知、未知设备的孤立移除通知不会直接生成插拔告警。
- 接口通知发生后复核物理设备是否真的出现或消失；同一设备在短暂驱动重置后恢复，或接口停止但物理设备仍存在时，不再直接锁屏。Windows 的持续清单变化需要至少 3 秒、多次成功观察一致后才确认。
- 清单与通知统一使用 VID/PID 和设备实例身份，忽略第三方 Win7 驱动的枚举器名称、REV 元数据；补充排除 SCSI/STORAGE/ROOT 等软件或存储子节点，保留同型号不同实例设备的区别。
- 新设备在两次心跳之间插入又拔出时仍保留事件；队列确认、重试以及会话切换保护继续有效。真实持续变化、明确检测失败仍上报告警并保留锁定。
- 外设原生扫描在通知核实和指纹轮询之间复用，减少旧电脑上同时启动的检测进程。日志新增 `usb-events`，区分接口抖动、确认的物理变化和检测组件故障。
- 指纹升级为 `usb-v6`。后台只在原始指纹未变且会话未锁定时迁移旧基线；同版本设备变化、降级及已有锁定不会被当作正常升级放行。

## 使用与复测

先部署本轮后台，再发布并安装 Windows 1.0.9，重新登录建立设备基线；只更新后台无法替换旧客户端的本机检测逻辑。不需要新增数据库字段。

在原来误锁的 Win7 SP1 32/64 位电脑上，保持无摄像头的原有配置，连续运行并检查键盘、鼠标及 USB 3 控制器是否仍误报；再插入新的 U 盘、持续拔掉外设，确认真实变化仍锁定且监考员可以处理。若再次锁屏，保留锁屏原文及用户数据目录 `logs/startup.log`，其中 `usb-events` 和 `peripheral-scan-failed` 可区分插拔告警与检测故障。

同一已知设备在确认窗口内物理拔掉又插回，与部分驱动重置无法可靠区分，会被防抖过滤；持续变化通常需数秒核实，加上心跳传输时间才显示告警。开发环境没有 Windows 7 真机，自动测试和安装包检查不能代替上述现场复测。

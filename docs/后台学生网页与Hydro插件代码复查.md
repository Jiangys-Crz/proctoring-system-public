# 后台、学生网页与 Hydro 插件代码复查

本轮以 `93d0220` 为基线，只核对代码并修复后台、学生网页和 Hydro 插件。没有修改桌面客户端、手机小程序或共享客户端运行库，没有新增数据库字段，没有构建安装包或部署服务器。

## 保存递交前重新检查权限

此前提交接口在读取 Hydro 语言列表之前验证会话与截止时间，网络等待后直接保存。因此，等待期间发生会话替换、锁定、结束考试或权限变更时，旧请求仍可能写入。

现在网络准备工作仍在事务外进行；保存阶段使用现有会话写入队列和行锁，重新读取会话、考试、考生和题目，核对当前令牌、锁定状态、已开始状态、考试时间、队长提交权限和语言限制。通过最后检查的时间同时作为原始提交时间。接口入口最多四个并发请求，有界等待；会话写入继续使用原有取消检查和事务重试。

请求体、成功响应和本地持久排队判题方式保持兼容；不需要更新桌面客户端。网络准备跨过截止时间或会话已替换时会拒绝保存，要求刷新或重新登录，不通过回填更早的时间绕过截止。

## 学生网页的并发刷新

- 全量考试读取、提交列表轮询和新递交使用同一读取版本，较早请求不能覆盖之后已经保存并显示的新递交。请求失败保留最近一次数据，后续轮询继续恢复。
- 公告推送和答疑轮询按“类型与原始编号”共用弹窗去重，不会因为两个通道先后返回同一记录而弹两份。同文但不同编号的回复仍分别保留。
- 已确认的近期通知暂存在有上限的本机内存集合，用于挡住确认之前已经发出的迟到读取。确认操作串行处理，按对应编号移除通知；不能连续点击而误移除下一条。网络确认失败会保留当前提示并显示重试错误，不把失败当作服务器已读。
- 打印记录改为请求完成后再安排下一次轮询，离开页面时取消请求；失败有提示，不再积累重叠读取或未处理的异步异常。旧读取不能覆盖刚新增的打印任务，提交失败保留输入内容。

## 打印接口的权限边界

新建打印任务现在在会话锁内重新检查令牌、锁定状态、已开始状态、有效考试时间及打印设置。已被替换、未开始、锁定或已结束的会话不能新建任务；已授权的历史记录读取仍可使用。

团队共享虚拟打印记录增加队名精确比较，避免数据库忽略大小写或重音时，把名称不同的队伍当作同队。实体打印仍限本人记录。打印接口使用有界考试请求队列，读取会话时只取题目摘要，避免每轮查询同时加载完整题面和私有配置。

## Hydro 插件的查询负载

插件升级为 `0.2.3`，包版本和配置检查返回版本保持一致。

- 每批最多 200 个记录编号，先校验、去重，再用一次限定题库域的查询读取，移除原先最多 200 个并行数据库查询。
- 批量查询不读取源代码，单条及批量状态响应不再重复输出代码。判题状态写回只需要结果字段，原始代码继续保存在监考数据库中；首次提交响应维持兼容。
- 非法编号可以忽略；数据库故障会返回失败，不再被吞掉后伪装成成功的空结果。
- 判题提交增加与监考后台相同的语言编号和代码长度限制。

查询调用已对照 [Hydro 上游 RecordModel 源码](https://github.com/hydro-dev/Hydro/blob/master/packages/hydrooj/src/model/record.ts) 的 `getMulti` 及投影方式核对。上游源码核对不代表已经验证服务器实际安装版本；本轮没有连接或重启 Hydro。

只更新监考网页不会更新 Hydro 当前启用的插件目录。后续部署须分别更新后台、学生网页和启用中的插件目录；本轮未执行这些生产操作。

- **Hydro 已有题目补写测试数据。** `problem/sync` 以前只在新建分支调用测试文件写入，现在更新已有题目也执行相同的文件写入。全部文件名与文本类型先验证，拒绝空段、目录穿越和规范化后重名；指定已有数字题号却查询不到时返回失败，不再另建不同编号。
- **旧登录票据回收与路径限制。** 签发和消费前回收过期票据，仍有效的票据最多 4096 个，满额时拒绝新增。等待用户查询期间也会再次核对上限。跳转使用规范化后的站内路径和目录边界，防止原始字符串前缀检查被目录跳转或相似目录名绕过。

Hydro 插件版本和配置检查报告统一为 `0.2.4`。测试文件更新采用上游 [ProblemModel.addTestdata](https://github.com/hydro-dev/Hydro/blob/master/packages/hydrooj/src/model/problem.ts) 的增量覆盖语义，不删除本次未提供的文件。多文件存储不属于同一原子事务；部分写入失败会返回失败，可以用原题号重试同名文件，不能据此认为多文件修改会自动回滚。查询上游源码未连接实际部署的 Hydro。

## 高并发与峰值内存复查

本轮以 `459923a` 为基线，只修改服务端及本说明，没有修改客户端、Hydro 插件或数据库结构。

- **语音上传补齐并发限制。** 学生端、监考端发送语音现在与其他普通上传共用进程级名额，默认最多四个活动上传，在读取表单之前领取，解析失败、权限拒绝和保存异常均在结束时释放。学生语音的频率限制也提前到读取表单前，配额仍在获得实际文件大小后扣除，避免大量请求先把完整语音读入内存、最后才被限流。单文件 8 MiB 和现有权限、时间校验继续保留；登录材料原有的独立保留容量不变。
- **判题扫描不预载整批代码。** 扫描最多 100 个待判编号和题目类型，领取任务后才读取该条代码，保持最多八个发送任务。读取时重新匹配租约时间和写入标识；已经被取消、替换或接管的任务不继续发送。结果写回仍有原来的条件保护，失败仍留在持久队列重试。这样不会在只发送八条时，保留其余 92 条完整代码等待。
- **Hydro 状态查询按实际连接批量请求。** 本地判题使用系统 Hydro 配置；此前按考试历史地址分组，会把同一服务的一页最多 200 个编号拆成许多并行请求。现在每页使用一次批量状态查询，保留现有同记录请求合并、结果写入保护、分页轮转，以及旧插件最多五个并发的兼容查询。没有更换判题服务或修改插件协议。
- **整场读取使用独立有界排队。** 监考状态最多两个活动读取、64 个等待位置，排队最多三秒。榜单新数据扫描与管理端概览共用最多两个活动任务、128 个等待位置，同样最多三秒。学生端同场榜单先加入正在进行的共享查询，再领取新扫描名额，保留同场并发请求合并；不同考试的待扫描映射也限制为 128 个。每个调用仍重新验证权限，完成后的成绩不缓存，封榜、历史时间点和客观题可见性仍由各自请求计算。繁忙返回可重试的 503，不无限积累数据库读取。
- **异常读取也等待已启动查询收尾。** 监考数据和共享榜单的并行查询统一等待全部已发起读取结束，再返回成功或抛出错误，防止第一条查询失败后立即释放名额，而其余查询仍继续占用连接，使后续请求不断叠加。
- **答疑长连接有总量和缓冲上限。** 每个进程最多 4096 条连接、128 场活跃考试，同一会话最多四条连接。鉴权和登记最多八个并行、128 个等待位置、三秒排队；该名额在连接建立后释放，连接总量由推送中心单独记录并在取消、断开、失效或慢读关闭时回收。每条输出缓冲从 256 KiB 降至 64 KiB，慢读者继续按原逻辑关闭；超限返回 503，沿用现有网页重连和答疑读取机制。
- **答疑补传扫描和突发结果有界。** 不同考试的推送扫描最多两个同时执行，按先后顺序等待，等待上限 128 个、最多一秒；未领取名额不推进连接进度。公告、回复和讨论变化每类最多读取 201 条，用第 201 条判断超过常规 200 条额度；已读回执最多读取 4001 条。超过额度时发送现有的不含私有内容的刷新事件，由正常答疑接口按持久未读批次补齐，避免把五分钟历史全部读入内存并逐连接广播。此过程不确认已读、不删除消息，也不改动内外网持久同步游标；会话验证仍发生在每次实际扫描中。

以上数字是资源保护边界，不是已验证的服务器容量。保留现有登录、会话写入、录制上传、答疑读写和内外网同步的独立限制；存储配置已有短缓存及进行中查询合并，本轮没有再增加配置缓存。排行榜计分、同毫秒并列首个通过、成绩身份和原始代码不变。

本轮仅做代码核对、TypeScript 静态检查和差异检查，未运行本地功能测试、压力测试或双端联调，没有连接生产服务器或部署。代码检查不能证明任意规模并发下都不会崩溃，实际容量尚未验证；本轮不需要新增数据库升级脚本或客户端安装包。

## 题库重测与迟到结果复查

本轮以 `09cda55` 为基线，只修改服务端与说明，不修改客户端、Hydro 插件或数据库结构。

- **题库状态刷新有写入条件保护。** 题库试做记录的列表和详情共用进行中的状态请求，最多四个活动刷新任务、128 个待处理标记，排队最多三秒。保存时同时匹配本机记录、原 Hydro 记录编号、原更新时间、状态及判题完成时间，迟到的旧查询不能把新重测误标成已完成，或覆盖另一查询已写入的最终结果。没有远端编号的新式本机编号不再被当作 Hydro ObjectId 请求；仍兼容以真实 ObjectId 作为旧本机编号的详情读取。

- **题库试做请求体也有上限。** 提交最多两个活动请求、64 个等待位置、五秒排队，在读取请求内容前领取名额；JSON 最多 4 MiB，代码最多 512 Ki 个字符、语言编号最多 64 个字符，与现有判题接口限制对齐。拒绝超限请求发生在调用 Hydro 之前，错误或保存结束后释放名额。该队列独立于正式考试提交。

## 旧版 Hydro 缺失记录与批量写入收尾复查

本轮以 `657b520` 为基线，只修改服务端及说明，没有修改客户端、Hydro 插件或数据库结构。

- **缺失旧记录不阻断同批有效结果。** 旧插件没有批量状态接口时，会回退到最多五个并发的单条查询。此前一组五条全失败就停止，若最前面的五条记录已在 Hydro 删除，后面的有效记录会在每次轮转时都被跳过。现在单条 404、410 作为记录缺失继续后续查询；认证、限流、服务错误或网络故障仍在一组全失败时停止。单页仍最多 200 个编号，兼容请求仍最多五个并行；完全缺少单条接口时也可能进行这一页内有限的 404 探测，未将探测改成无限重试。已有批量接口的正常路径不变。
- **刷新任务等全部已启动写入收尾。** 同一轮共享状态任务和每组最多五个结果写入，现在等待全部已经启动的操作结束，再返回或抛出错误。避免第一条数据库写入失败后过早移除进行中标记、下一轮再次开始，而旧操作仍占用连接。写回继续匹配原判题编号和写入标识，迟到结果不能覆盖重测、取消或远端导入的新状态；没有将错误当作成功。

排行榜继续使用本机已保存的结果和原有计分规则，不因这些错误分支修改原始递交时间或代码。答疑推送回执范围的修复见 [公告答疑复查说明](公告答疑双向同步与并发复查.md)。

## 代码导出与本机文件下载的峰值资源复查

本轮以 `3c7456e` 为基线，只修改服务端、数据库索引定义与说明，没有修改客户端或 Hydro 插件，没有构建安装包或部署服务器。

- **代码导出不再缓存整场代码和整个 ZIP。** 原先先查询全部代码及判题详情，再生成完整压缩包，并为响应复制一份数据。现在每页只读最多 128 条导出元数据，使用创建时间和编号继续扫描；起始时固定创建时间上界，不追逐考试中持续新增的提交。代码按 ZIP 当前文件的需要读取，每次最多 32768 个数据库字符，按数据库字符数推进，保留中文、表情、换行及原始代码。只读取当前源文件，不建立覆盖整个下载的数据库事务。分片会增加代码查询次数，以单个源片段的内存上界换取资源稳定。
- **ZIP 内容与清单流式输出。** 使用已安装的 yazl，采用低档 DEFLATE 压缩，浏览器变慢时停止继续拉取源数据；CSV 按行输出，不再构建一整份 CSV 字节缓冲或 ZIP 响应副本。每登记 128 个文件让出一次执行机会，避免一次同步登记大量文件持续阻塞登录和心跳处理。目录和 CSV 元数据仍随记录数增长，不能据此声称任意规模下内存恒定。导出仍含程序代码、提交清单和说明，继续排除客观题及答案提交题；CSV 的原有分数字段语义不变。文件名加入本次导出序号，避免同时间、相同编号尾缀或路径字符替换产生重名；清单记录实际路径和完整编号。目录名称统一限制长度，避免姓名、考号拼接后过长。
- **导出名额覆盖完整传输和迟到查询。** 每进程最多一个代码导出、两个等待位置、五秒排队；排队在读取导出元数据之前。导出和传输共用十分钟期限，取消、超时、源数据错误会中止下载并关闭当前源流。已经发出的 Prisma 查询无法直接取消，名额会等该查询结束后才释放，迟到结果不能启动下一块读取。传输开始后的失败会使下载中断，不能将不完整压缩包当作成功导出，应重新下载。HEAD 只验证权限和返回响应头，不扫描或打包代码。
- **本机文件下载按字节限制缓冲。** `/api/uploads/file/...` 改为按需从 Node 流拉取，Web 队列按字节计算、背压阈值为 64 KiB，文件读取缓冲同为 64 KiB；避免默认按块计数时，慢连接提前读入大量录像。取消后立即销毁源流，等待中的读取迟到时不再向已关闭响应写入。签名、过期时间、删除标记和本机真实路径检查继续保留。
- **图片与长媒体分别排队。** 图片最多八个活动下载、128 个等待位置，其他本机文件最多四个活动下载、64 个等待位置；排队最多三秒。名额覆盖实际响应体，图片期限仍为一分钟，录像等长媒体为五分钟，失败或取消后释放。这样长时间播放不会用尽图片名额；RTMP/HLS 推流及题目附件原有的独立队列不变。HEAD 不打开正文流、忽略 Range；普通 Range 继续返回部分内容，超出安全整数范围的请求返回 416，不误转成整份文件下载。

新增 `ContestSubmission(examId, createdAt, id)` 索引，配合元数据分页与本场按时间读取，避免大表分页反复排序。升级脚本为 [20261105-code-export-index.sql](../deployment/migrations/20261105-code-export-index.sql)，或采用当前完整 schema 的项目升级流程。脚本只新增索引、不可重复执行；建索引会产生数据库负载，需安排发布窗口并先备份。本轮没有连接数据库执行脚本。

分页导出不是冻结数据库的一致性快照；扫描期间发生删除会中断源文件读取，离线补传或管理员变更也可能影响扫描时可见的元数据。没有修改成绩、计分规则或提交代码。所有资源上限均为代码保护措施，不代表已验证的并发容量。本轮仅做代码核对、TypeScript、Prisma schema 静态校验和差异检查，未运行本地功能测试、ZIP 解压验证、真实下载或压力测试，未连接生产服务或部署。

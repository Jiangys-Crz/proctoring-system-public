# 公网、内网题库与考试同步

同步由内网单向发起连接，资料仍可双向修改和交换。内网无需域名、公开地址、端口映射或供公网访问的 API Key。

1. 公网进入「系统设置 → 公网与内网题库、考试同步」，选择并保存「公网版本」，点击「生成并启用 API Key」。密钥由服务器生成、加密保存，点击后即生效；重复点击或请求失败后重试会返回原密钥。已有密钥可由超级管理员查看和复制，不会自动更换。
2. 内网选择「内网版本」，只填写公网服务器根地址（例如 `https://proctoring.example.org`）及公网生成的 API Key，勾选启用并保存。已有密钥留空即保留。
3. 公网只需保持同步启用，无需填写内网地址或密钥。内网主动上传本机改动、拉取公网改动以及传送题目文件；公网接口只接收请求，不回连内网。

公网自身地址由部署的 `APP_BASE_URL` 提供，不要求在同步设置中重复填写。每组连接当前对应一个固定公网节点和一个固定内网节点；不要将同一公网节点的同步进度混用于多台独立内网数据库。已有映射不能直接切换角色或替换节点。

两端「评测服务设置」分别连接各自的 Hydro，并选择要使用的题库域。监考系统与对应 Hydro 插件配置的域必须一致。插件的同步接口始终使用这个域，不接受调用方指定其他域。

内网主动发起资料交换、上传本机题目文件和下载公网题目文件，因此公网服务器无需主动访问内网。请保证内网服务器能访问公网服务器，两台监考服务器各自能访问本端 Hydro。正式使用时为公网连接配置 HTTPS。

## 发布与导入

1. 在公网发布本平台答题考试，选择题目，配置考生及考室，打开「考试管理 → 公网与内网同步」的「同步本场考试」。
2. 在内网进入「添加考试」，选择「导入公网考试」，粘贴公网考试详情链接。考试编号保持一致，内部数据库 ID 可以不同；重复导入复用已建立的记录。
3. 后续两端均可修改考试、题号和分数、考生及考室。资料通常每 3 秒交换一次，提交、评测结果和答疑公告沿用独立的同步队列。网络或依赖暂时不可用时保留进度并重试。暂停某场考试不会丢弃已收到的待处理更新，恢复后继续处理。

没有导入的其他考试不会自动创建或被覆盖。本地同编号但未建立同步关系的考试会阻止导入，避免误覆盖。当前跨网考试同步面向本平台答题、Hydro 判题的考试。

同步内容包括考试设置、管理员与监考安排、考生资料及成员排序、题目映射、代码、判题及人工评分、排行榜所需数据、答疑公告及其图片与已读记录、登录审核和会话状态、身份照片、打印、作弊与告警记录、控屏图片与计划、代码查重报告。录像、环境视频、登录 IP 限制及 IP 绑定保留在各自服务器。设备标识、会话令牌、判题任务租约属于本机运行凭据，不复制；导入的会话和查重任务不会在另一端重新启动本机采集或分析任务。

双向修改按记录的逻辑版本和固定节点标识收敛；同一条记录离线同时修改时，版本较高者获胜，版本相同时按节点标识确定一致结果。跨节点替换和落后的不同内容会保存到 `SystemSetting` 的 `platform-conflict:` 历史快照，供管理员恢复；这不是字段级自动合并，仍应避免两端同时编辑同一条尚未同步的记录。考室归属按考生独立记录版本，不再通过多个考室名单相互覆盖。新导入考生在收到首次分配前标记为“尚未同步”，不会把默认空考室当作本机清空操作；本机明确调整考室仍会正常同步。删除考室会等待相关分配变更落库，避免级联清空被误当作本机修改。

## 题目身份、修改与删除

- Hydro `docId` 是内部数字编号，`pid` 是可修改的展示题号。导入、判题和题库映射使用 `docId`，修改 `pid` 不会创建新题或改变映射。删除后重新创建并复用数字编号的题目，会结合 Hydro 原生文档身份识别为新题，不会改写旧考试的题目。映射还具有独立的同步标识，两端 `docId` 不同也能对应。数字编号被新原题复用时，旧考试题目会切换到独立的已删除身份，并保留原提交和答疑对应关系，不占用新原题的映射。
- 考试题号是本场单独设置的显示编号，最多 6 个字符，默认 A、B、C……，例如 L1-1。它不覆盖 Hydro 的内部 ID。
- 题目对应关系以同步标识及 Hydro 原生文档身份为准，不再仅凭相同题面或文件内容合并已有题目，避免误合并独立原题及删除另一道题。不同来源的相同内容可以保留为不同题目。同步文件使用 SHA-256 内容校验，与 Hydro 存储提供方的 ETag 无关。文件先写入不可变暂存区，按清单检查大小与校验和，全部齐备后才应用；重试仅请求缺失文件，未改变的文件可复用。内容相同但逻辑版本较新时仍更新版本标记；应用、确认和异常状态写入会核对完整传输版本，旧任务不会清除新任务的状态。替换前在 Hydro 的 `proctor-sync-backup/` 存储前缀和 `proctor.sync.backups` 集合保留旧文件及元数据。
- 源题删除会同步删除标记，避免断网重连后复活。已结束考试保留本地题面、代码、提交记录和成绩，标记为不可重测；未结束考试也停止向已删除的源题提交。题面里的历史外部资源不在本地快照内时，导出使用现有缺失资源处理方式。

## 断点、重试与记录保护

- 传输采用至少一次投递。响应丢失或超时后可能重复发送请求，接收方按固定记录 ID、逻辑版本和内容校验进行幂等处理；重复请求不会因此插入多份业务记录。
- 已落库的相同或较旧版本不会再次进入待处理队列；写入层也禁止版本回退和同版本异内容覆盖。收到的待处理资料先持久化，再推进进度；依赖暂未到达、考试暂停和写入失败均保留队列。删除队列项时核对处理的完整版本，避免旧任务误确认后来收到的新版本。
- 分页读取使用一致的事务快照及序列上界。导入考试使用按依赖排序的不可变快照，有效期 30 分钟；过期可重新导入，已建立的映射继续复用。资料暂未满足依赖时，系统设置显示待处理数量及错误，不把待处理队列当作已全部应用。
- 任务在启动、写入及提交进度前检查租约和配置，失效任务不能继续提交数据库修改。全局连接与考试连接的密钥变更在同一事务保存；配置发生变化会撤销旧任务，避免一端已经换密钥、考试连接仍沿用旧密钥。交换和文件推送前校验对端固定节点身份，替换服务器数据库后不会继续套用旧进度。已有同步历史不能直接更换节点角色，已有题库绑定不能直接切换 Hydro 连接或题库域，修改设置时即拒绝；每次文件请求固定使用开始时选择的域。
- 公网文件补传准备必须来自已经绑定的内网节点。暂存记录固定目标 Hydro 地址、题库域和题目版本；长时间上传结束后再次核对配置及暂存记录，发生变化时保留补传任务并重试，不改写新版本。上传只暂存字节，所有文件齐备后才应用并确认整道题。公网扫描本机题库不会刷新“最近资料交换”时间。
- 最新补传每轮最多顺序传送 16 个文件，开始下一文件前核对 20 秒时间预算及 32 MiB 批次预算；第一份大文件可单独流式传送，沿用 5 分钟超时。已经上传的不可变文件保留，下一轮只补缺失文件；完成字节上传后仍等待公网版本确认，不提前移除任务。此优化需要更新内网后台。
- 文件准备记录不是上传完成证明。公网只在 Hydro 返回缺失清单为空时应用题目；未完成的同步题目不出现在监考平台的可用题库搜索中，按编号导入也拒绝未完成题目。Hydro 内部可能已经建立隐藏占位题，其数量增加不代表测试数据和附件已经到齐。
- 同步设置每 15 秒刷新状态，按原因汇总待处理记录，最近资料交换时间只代表元数据请求成功。接收文件失败单独保存版本对应的原因，近 30 分钟错误可由超级管理员查看；该错误不重复计入待处理数量，成功上传及题目确认后会清除。公网收到近期内网交换时不再额外每三秒重扫题库争抢同一同步租约。
- Hydro 题库锁记录主机及进程身份。同主机确认旧进程已经退出时，按原锁令牌有条件释放遗留锁，避免重启后等待完整的 15 分钟租期；仍存活的进程、其他主机、PID 被复用及缺少身份的旧锁均不会被自动清理。旧版无身份锁的维护清理须先确认所有可能持有锁的 Hydro 服务已停止，并保留锁记录备份。
- 题库同步另显示“已核对题目数”和“已到齐文件数”。文件计数取自 Hydro 返回的缺失清单，只统计当前收件版本，旧版本及已完成题目的进度不混入；该记录仅用于显示，不作为应用成功或推进游标的依据。状态页面聚合小型进度记录，不为刷新进度下载题面或测试数据。尚未核对的题目不记为零缺失，文件到齐仍须完成应用和版本确认。
- 源题删除、控屏分组软删除及其他删除标记不会被扫描重新发布为新增记录。移除考试题目时保留历史行并禁用源题使用；考生已有提交、会话、答疑、查重等考试记录时禁止级联删除，远端删除请求保留在待处理队列中。
- Hydro 文件应用与监考数据库属于两个存储系统：Hydro 应用后仍保留待确认标记，待监考数据库保存映射与版本后再确认；中断后根据已保存版本补确认，避免把应用中的文件误判为本机新修改。直接在 Hydro 编辑同一题时会核对版本；检测到冲突后停止继续确认并保留暂存和恢复副本，需按错误提示核对。文件应用涉及 Hydro 自身的文件操作，不应把这套恢复机制理解为跨数据库、跨文件系统的单一原子事务。

## 考生与计分

个人模板：姓名、考号、密码、考室、座位号、组别、学校、学院、年级、学号、是否排名，专业和班级可留空。团队模板另有队伍名称与成员次序，每人一行，按队名匹配；1 号是队长，其余为队员。

分账号团队每人填写账号密码；共用账号团队仅 1 号填写账号密码，其他成员留空，系统保留每人的资料并组合成一个队伍登录账号。旧版聚合成员姓名与学号字段仍可读取。考生登录只需考试编号、考号、密码，身份资料由导入记录取得。

考试分数就是该题本场满分。例如原题满分 200、本场设置 70，原题得 100 时本场得 35 分；各赛制原有取整规则继续适用。人工评分仍是本场最终分数。刷新或重新导入已有题目时保留本场分数和题目位置，只有明确提供的新分值才会覆盖；新增题目追加到空闲位置，重复原题会被拒绝。

考试结束前，服务端拒绝试卷和代码导出（含代码 HEAD 探测）。代码 ZIP 使用「学号-姓名/题号-题目名-提交编号.语言后缀」，保留原始提交编号并替换文件名非法字符。

人工评卷仅在 KS 赛制的整场考试结束后开放，以考试当前 `endAt` 为准，个别考生提前交卷或灵活考试的个人时长结束不会提前开放评卷。评卷数据读取、保存人工分和恢复系统分均由服务端检查；保存事务内再次读取并锁定考试，延长结束时间后，旧页面不能继续提前保存评分。该限制针对人工评卷，程序自动判题仍按原赛制运行。

## 已有安装升级

本轮出站连接设置调整只需更新两端监考后台网页服务，不涉及考生客户端或 Hydro 插件版本、数据库表结构及同步协议变更。旧版保存的内网地址和回连密钥不再使用；原公网密钥、固定节点、题目映射及补传进度保留。首次由旧的逐考试连接迁移时，可以先保存全局角色及公网连接，再按下述方式迁移已有考试；不会因为尚未迁移的旧考试连接阻止设置内网角色。下面记录的是此前完整同步功能的安装要求。

本次同步协议为 `platform-sync-v3`，两端监考服务与 Hydro 插件必须一起更新；旧协议会明确拒绝交换，避免不完整的考室分配或导入快照。两端均需更新监考网页、考生网页和桌面客户端，同时替换 Hydro 的 `cwnupaa-proctor-auth` 插件目录并重启 Hydro。只更新网页无法启用题目文件同步。

已有数据库在备份后审查并执行 `deployment/migrations/20261106-platform-sync.sql`，然后生成 Prisma Client、重新构建并重启服务。该 SQL 是一次性增量迁移，包含新表、新字段及旧团队成员排序恢复；不要在已经应用这些字段的数据库上重复执行整份 SQL。也可按原部署方式运行 `pnpm db:push` 补齐结构，该命令会运行幂等的团队排序恢复脚本。保留各服务器自己的环境文件、数据库、存储和上传卷，不需要清库或重新初始化考生。

本次提交补传隔离增加 `ContestSubmission.federationAttemptAt`、`federationError` 和重试索引。已有同步数据库还需单独应用 `deployment/migrations/20261106-submission-sync-retries.sql` 中尚未存在的结构，或由原 `db:push` 流程补齐，再生成 Prisma Client 并更新服务。两份增量 SQL 均不可在已包含对应结构的数据库上整份重复执行；本轮仅提供代码和迁移文件，未执行数据库操作。

已有旧版跨网同步连接时，先在两端配置全局连接，在公网页面打开新的考试同步开关，再在内网重新导入同一公网考试链接。系统核对原先绑定的公网节点，保留考生、题目、代码、讨论及节点来源，只重建传输索引和统一映射；不匹配的旧节点或普通同编号考试仍会拒绝覆盖。

## 本轮同步与并发审查

- 旧答疑另设持久化扫描进度，补齐未标记待同步的历史首问、旧回复和公告。每条资料独立整理，异常记录保留并记录尝试时间，其他记录继续补传；修复旧首问的来源时，导出使用修复后的原始来源，避免复制到另一端的首问被误当成本机新增。
- 同版本、同内容的答疑重放不再增加同步序列。消息和公告保留首次发布的不可变快照；两端独立回复以各自消息编号追加，不按相同文字合并。公开状态按胜出版本收敛，并恢复该次发布的公告、撤回其他发布批次及缺少批次标记的历史公告。
- 图片按数量和字节预算分批整理，未入选的原图不会被当作删除。暂不可读的身份照片、控屏图片保留元数据并退避重试，在同步状态中计入待处理数量；未保存本地图片修改前，远端非删除更新继续等待。答疑图片索引存在而实际图片记录缺失时，可在重放时补回图片，已有图片仍检查来源、大小、哈希和访问密钥。
- 全局资料交换、文件传输、排行榜和评卷读取分别限制在途数量与排队长度，繁忙时返回可重试状态。同步页、持久化收件队列和导入快照先读记录身份，再逐条读取图片或代码内容，避免先把整批大对象装入内存后才应用发送大小限制。查重源码和结果分批读取；收到远端查重更新时，单独锁定并保存对应本地结果，避免受下一批扫描位置影响。
- Hydro 题库逐页处理，只有完整扫描成功后才判断删除。文件 SHA-256 以 Hydro 不可变物理文件身份复用缓存，逻辑路径被新文件替换时重新计算；每道题顺序检查文件，避免无限并行读取。中断后的题目确认按页恢复，不为每条题目递归重扫整个题库。控屏及照片读取复用存储连接，限制完整读取时间及实际字节数，超时关闭流。
- 学生排行榜、后台总览和评卷分别使用一致的数据库快照读取规则、分值与结果。学生端同场榜单短暂合并读取和计算，并限制缓存总量；权限检查每次重新进行。团队展示按成员次序选择队长和排序，毫秒相同的首个 AC 按固定提交编号确定；最高分选择考虑人工评分。评卷仅加载每位考生各题最新有效提交的代码，减少轮询重复读取历史代码。考试分值和历史人工分通过不同队列到达时，保留原人工分，避免仅因当前满分已变化而卡住提交同步。

同步仍为至少一次投递，网络恢复前两端可能暂时不同；同一记录同时修改使用版本规则收敛。这些代码调整不构成并发容量或跨存储零故障的实测结论。本轮未修改桌面、小程序、考生网页或后台交互组件。

后续代码复核继续修正了以下边界：
